## ELI5

The bot asks Claude questions. Today it asks the older, pricier Haiku 4.5. The operator wants it to ask the new Haiku 5.5, which is about 10x cheaper per token and smarter. The model name is copied in five places; we put it in ONE place so this never has to be hunted again. Haiku 5.5 also refuses one setting the bot always sends (`temperature: 0`), so that must go or every call fails. Then we prove it works: tests pass, one real call answers as Haiku 5.5, a small side-by-side run shows it labels defects at least as well as before and what it cost, and the restarted bot prints the new model name in its log.

## Intent (what and why)

**What.** Every Anthropic call monday-bot makes — the Slack answer generator, the Jira natural-language filter mapper, and the three operator scripts (feature-flow eval, catalog build, label backfill) — defaults to `claude-haiku-5-5`, with the existing `ANTHROPIC_MODEL` environment override preserved for per-run swaps.

**Why.** Operator ask 2026-10-15 (verbatim): "I want monday bot to run on haiku 5.5." Haiku 5.5 is the current Haiku-class model: 1M context, better instruction following, and a far cheaper rate card.

**Price (official, fetched 2026-10-15 from platform.claude.com/docs/en/about-claude/pricing):**
- Claude Haiku 5.5, prompts up to 100,000 tokens: **$0.10 / MTok input, $0.50 / MTok output** (5m cache write $0.125, 1h $0.20, cache hit $0.01).
- Claude Haiku 5.5, prompts over 100,000 tokens: $0.50 / MTok input, $2.50 / MTok output.
- Claude Haiku 4.5 (today): $1 / MTok input, $5 / MTok output.
Every monday-bot prompt is far below 100K tokens (the eval budgets 2,050 input tokens per defect), so the low card applies. The bundled `claude-api` skill's cached table (2026-10-06) agrees.

### Request-shape changes Haiku 5.5 REQUIRES (source: bundled `claude-api` skill, `shared/model-migration.md` § "Migrating to Claude Haiku 5.5")

1. **`temperature: 0` returns HTTP 400 on Haiku 5.5** ("non-default sampling parameters return a 400 ... `temperature` must be `1`"). ALL FIVE call sites send `temperature: 0`, and `tests/generate.test.ts:77-90` pins it (determinism doctrine #1195). An id-only swap would break every call. The sampling field must be dropped and the pin rewritten.
2. **Thinking is ON by default and counts toward `max_tokens`.** Two scripts cap at 256 and the filter mapper at 512; a reply could stop after an empty thinking block. The skill's remedy: leave `thinking` unset and send `output_config.effort: "low"` on short classification routes (and keep the cap at or above room for a short think + answer). All five sites already extract text by block TYPE (filter on `type === "text"`), so the "first block is thinking" hazard does not apply.
3. **Tokenizer counts ~30% more tokens for the same text.** The eval's fixed `PER_DEFECT_INPUT_TOKENS = 2050` projection is now a 4.5-era number; the cost line must be labelled as a projection on the new rate card, and the comparison AC reports measured `usage` where it can.
4. Not applicable here: `budget_tokens` (never sent), assistant prefill (never sent; every `messages` ends on a user turn), computer use, multi-turn history edits (all calls are single-turn).

## Decisions (what, not how)

1. **One source of truth for the default model id.** A single module under `src/llm/` owns `DEFAULT_MODEL = "claude-haiku-5-5"` and the `ANTHROPIC_MODEL`-override resolution; `generate.ts`, `nlFilterMapper.ts` and the three `scripts/*.js` (which already `require` from `dist/`) consume it. No literal model id remains anywhere else in `src/` or `scripts/` except that module (AC-2). `tests/` is the one place a literal MAY appear, and only in assertions that pin the module's default (AC-4) plus the stub's `claude-haiku-stub` sentinel — a test that quotes the expected id is the oracle, not a second source of truth.
2. **Keep the `ANTHROPIC_MODEL` env override** (CHANGELOG #18/#51 contract). Precedence unchanged: env wins, else the default.
3. **The same module owns the rate card** (`$0.10 / $0.50` per MTok, Haiku 5.5 <=100K card, dated + source-cited in a comment) so the eval's `PRICING` and any future cost line share one number. `estimateCost` stays pure and its unit test keeps its inline 4.5 numbers (it tests arithmetic, not the model).
4. **Drop `temperature` everywhere; rely on prompt wording + low effort for determinism.** The #1195 test becomes "sends NO sampling parameter and the resolved default model id". Determinism doctrine is preserved by the CHANGED-directive retry design (`generate.ts:515-518` already says the retry differs by directive, not by temperature). **In scope for AC-3 (every `temperature:` mention under `src/` and `scripts/`, 9 lines at HEAD):** the 5 request fields (`src/llm/generate.ts:526`, `src/jira/nlFilterMapper.ts:263`, `scripts/feature-flow-eval.js:90`, `scripts/build-catalog.js:83`, `scripts/backfill-namespaced-labels.js:192`), the REQUIRED `temperature: number;` field of the `MessagesCreate` type (`src/jira/nlFilterMapper.ts:35`), and the doc comments that quote the pin with a colon (`src/triage/growthProposer.ts:5`, `src/triage/featureFlowMatcher.ts:7` and `:58`) — reworded to describe the new determinism lever. Accuracy-only (they say "temperature 0" / "raised temperature" without a colon, so they do NOT match the AC-3 pattern): `src/jira/nlFilterMapper.ts:10`, `src/llm/generate.ts:485,517`. Outside AC-3 but updated for accuracy: the stub's comment at `tests/__stubs__/anthropic-sdk.js:6`. `scripts/eval-golden.js:124` ("temperature per generate.ts", no colon) is not matched by the AC-3 pattern and may be reworded or left.
5. **Short classification routes send `output_config.effort: "low"`** (mapper, feature-flow eval, backfill). The answer generator and catalog distiller keep the model default (`medium`). Caps stay >= 256 so a short think + answer fits; the smoke/eval ACs catch truncation (`stop_reason: max_tokens`) if it still occurs.
6. **The bot prints its resolved REQUESTED model id once at startup** on a `llm-model: <id>` line next to the existing `build-stamp:` line (counts/ids only — the id is public information, no secrets). The value is the id the module resolved (env override or the literal default) — NEVER an API-returned `res.model`, which may carry a date suffix and would break AC-9's anchored grep (cairn lesson above). This is what makes AC-9 checkable from the launchd stdout log.
7. **`feature-flow-eval --real` gains a `--limit N` sample control** so the A/B comparison runs on a small FIXED sample (the first N open defects in the fetcher's stable order) instead of the whole backlog. Default stays unlimited (no behaviour change for existing operator use).
8. **`dist-last-good/` is NOT hand-edited**; it is promoted by the launchd wrapper after a green build. Not in this ticket: Bedrock/Vertex ids, prompt rewrites, SDK bump, any `.env` change.
