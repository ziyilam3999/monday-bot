## ELI5

The bot does not know it has a name. The standing instructions sent with every answer (SYSTEM_PROMPT in src/llm/generate.ts) never say "you are Monday Bot", so when a user writes "Monday, can provide business rules for dispute resolution?", the answer model reads the name as the weekday and opens with whether someone can provide them *on Monday*. Two small things, both inside that one file, fix it. First, the standing instructions get a name tag: the model is "Monday Bot", users call it "Monday" or "monday-bot", and a name in call position — leading "Monday, …", right after a greeting ("hey Monday …"), trailing "…, Monday?", or an @mention — is someone talking TO the bot: never a date, never question content; a weekday used as an actual date keeps its date meaning. Second, a tiny deterministic cleaner removes exactly those name-call tokens from the question text before it is handed to the model, reusing the ONE name list (BOT_NAME_TOKENS) the Telegram greeting gate already ships — no second list anywhere. A real weekday ask ("what was deployed on Monday?") passes through byte-identical, and "Monday, what is due on Monday?" drops the name-call but keeps its date. Everything upstream — adapters, the help gate, the exact-key leg, the ask log — sees the original text exactly as today.

## Problem (why)

Verified in code. `generateAnswer` (src/llm/generate.ts:443) builds `Question: ${question}` verbatim into the user message (:473–476) under SYSTEM_PROMPT (:10–36), which nowhere mentions the bot's name or identity — so "Monday," at the head of an ask is free to be parsed as a weekday, which is exactly what the operator saw ("Whether someone can provide them on Monday isn't covered anywhere"). Both surfaces feed this one seam (telegram/adapter.ts:193 and slack/adapter.ts:174/229 → handleQuery → KnowledgeService.query), so the misread is surface-independent. Meanwhile src/telegram/helpGate.ts:51 already exports BOT_NAME_TOKENS ("monday", "monday-bot") and its greeting arm already treats those tokens as a vocative — but only inside the card gate; the question path into retrieval and generation never uses it.

## Determined boundaries (and why)

**B1 — One file, one seam.** All production changes land in src/llm/generate.ts: (a) the identity/vocative clause appended to SYSTEM_PROMPT, and (b) a pure exported name-call cleaner applied to the question exactly where the `Question:` line is built — before the model ever sees it, downstream of the empty-chunks and offline/test-mode guards (those paths never build a user message). The backstop retry reuses the same cleaned user content for free. Size stays S: one code file plus tests; no restamp.

**B2 — Matcher data is borrowed, never copied.** The cleaner imports BOT_NAME_TOKENS (and, for the greeting-adjacent arm, GREETING_LEXICON) from src/telegram/helpGate.ts — pure constants, no I/O. helpGate.ts itself is untouched. No second name list is created anywhere.

**B3 — Fire arms (conservative: ambiguity → keep).** Matching normalization (case-fold, strip end punctuation, fold "_" as "-" for mention usernames) is INTERNAL to the cleaner; on any non-match the input is returned byte-identical (the #3299 parity convention applied at this seam). Arms:
- **Leading**: the first token normalizes to a name token AND is comma-announced (trailing comma on the token, or a standalone comma token next) → remove the name token and its announcing comma. Comma-gated on purpose: "Monday what was deployed" (no comma) is genuinely ambiguous between vocative and date-subject, and the doctrine keeps it (the prompt clause is the guard there).
- **Greeting-adjacent**: the first token normalizes into GREETING_LEXICON and the second token normalizes to a name token → remove the name token, keep the greeting word. The greeting itself is today's noise and is not misread as a date; only the name-call is.
- **Trailing**: the last token normalizes to a name token AND the preceding token announces it with a comma → remove the name token and that comma. "what was deployed on Monday?" (no announcing comma) never fires.
- **@-mention**: any token beginning "@" whose remainder (separator-folded) equals a name token → remove the token. Position-free but name-matched: a mention of THE bot is a call to the bot, never question content; mentions of anyone else are untouched.
Arms are independent and may compose ("Monday, what is due, Monday?" cleans both ends).

**B4 — Prompt clause content (intent; executor words it).** The clause must (1) name the assistant (Monday Bot, addressed as "Monday"/"monday-bot"), (2) define name-call positions as vocatives — never a date, never content, never a deadline the user is waiting for, and (3) explicitly preserve weekday-as-date readings elsewhere in the question. It must not alter any existing grounding/citation/abstain rule: the existing prompt-integrity assertions stay green (no drift), and new assertions pin phrases for (1)–(3).

**B5 — Upstream untouched.** No adapter, helpGate, queryHandler, or knowledge-service change; retrieval still embeds the raw question exactly as today (deliberate: keeps the diff one file and the #3306/#3299 parity guarantees intact; retrieval hygiene is not an AC). Slack's `<@U…>` strip stays as is — name-calls typed as words ("Monday, …") on either surface are what this plan fixes, at the one shared seam.

**B6 — No new knobs.** No env var, config, or kill-switch for the cleaner or the clause: both are total pure text transformations with a byte-identical default path; the existing test suite is the guard (mirrors the #3306 B10 cost stance).

## Named risks

- **Comma-less leading name-call** ("Monday can you help") is NOT cleaned (B3 leading arm is comma-gated; ambiguity → keep). The prompt clause is the only guard there. Accepted edge; execution-review condition: tighten only if the ask log shows real comma-less name-call asks going wrong.
- **Trailing comma-shape could theoretically eat a genuine trailing date** ("the deploy is due Friday, Monday") — an unnatural shape; the announcing-comma rule plus the prompt clause bound it. No AC arm.
- **Identity clause could shift answer tone** (model signing as Monday, addressing users). The clause is scoped to interpretation, not persona; the existing golden/prompt-integrity corpus guards tone drift. No persona AC in v1.
- **Retrieval still sees the name-call** (unchanged from today) — named so nobody mistakes it for an oversight; widening to the retrieval seam is a follow-up only if recall measurably suffers.
